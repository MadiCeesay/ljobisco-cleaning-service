# Sequential validation plan

1. Foundation: environment validation; strict origin allowlist; safe errors and logs; health/readiness; replica-set requirement; graceful shutdown. Gate: foundation HTTP tests and lint.
2. Accounts: hashed passwords, customer-only registration, email links with hashed single-use database tokens, random opaque server session cookies, synchronizer CSRF, rotation/revocation, profile ownership, private administrator bootstrap. Gate: actual replica-set registration/verification/reset/session integration tests. Email test dependency is a capture transport; no claim of real SMTP delivery.
3. Cleaning: customer-owned request records, approved service slugs, administrator-only itemized revisions, compare-and-swap booking revision/current-version checks in transactions, immutable accepted snapshot and expiry. Gate: cross-customer denial, stale/expired/revised offers, concurrent acceptance.
4. Private communication: durable messages, authorized paginated history/read watermark, shared HTTP/socket authorization, reconnect refresh, bounded and inspected image uploads to authenticated Cloudinary assets. Gate: participant denial, role checks, byte validation, live local socket handshake/room tests with ephemeral database. Provider credentials remain external blockers.
5. Commerce: administrator-managed inventory, configuration-required fulfilment, integer minor amounts, atomic stock changes, idempotent order/payment commands, accepted quotation snapshots and completion-locked balance. Gate: concurrent inventory, duplicate commands, server-side mock settlement and booking-to-deposit/product-order scenarios. Real provider adapters fail closed.
6. Management/integration: role-guarded metadata mutations and complete workspace DTOs, catalogue/cart/checkout/payment/upload/socket adapters, docs and full regression checks. Do not alter approved visual architecture. Gate: backend/frontend lint/tests/build, real local HTTP integration and production mock guards; document any unexecuted provider/browser test honestly.

MongoDB transactions must not use parallel operations within one transaction. HTTP mutation retries need client idempotency identifiers, not automatic replay. Backend service DTOs return presentation GMD decimals while persisted monetary fields are integer minor units. Upload records bind ownership and purpose; user-submitted remote URLs are never fetched or accepted as attachments. Private media must be authorized afresh before redirecting to an expiring signed URL. Every missing merchant, contact, fee, catalogue or fulfilment detail remains explicitly unavailable.
